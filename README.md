# hh-autoapply

Автопоиск и автоотклик на hh.ru. 

## Перенос на другой компьютер

1. Скопируй папку `hh-autoapply` на новый комп (архив `hh-autoapply-transfer.zip` уже
   без лишнего — без `.venv`, `state/`, `.env`; ставится с нуля).
2. На новом компе нужен **Python 3.9+**. Проверка: `python3 --version`.
3. В папке выполни установку (один раз):
   ```bash
   bash setup.sh
   ```
   Скрипт создаст окружение, поставит зависимости и браузер Chromium.
4. Запусти дашборд:
   ```bash
   bash start.sh
   ```
   и открой http://127.0.0.1:8000
5. В дашборде: **«Открыть окно входа»** → залогинься в hh.ru руками → **«Я вошёл — сохранить»**.
6. Впиши **API-ключ ИИ** в блоке «ИИ для писем» → «Сохранить» (ключ не переносится в архиве).
7. Выстави фильтры → «Запустить прогон».

Что НЕ переносится (создаётся заново на новом компе):
- `.venv/` — окружение (ставит `setup.sh`);
- `state/` — сессия hh.ru (перелогинься), список резюме, кэш, лог;
- `.env` — конфиг с ключом (задаёшь через дашборд заново).

Почему сессию лучше создать заново: куки hh.ru привязываются к устройству/сети —
надёжнее войти на новом компе, чем копировать `state/session.json`.

Два варианта транспорта, общий движок решений [decide.py](decide.py):

- **Браузер (Playwright)** — основной. Отклик по API закрыт для сторонних приложений,
  поэтому ходим через сайт под твоей залогиненной сессией. Файлы: `login.py`,
  `browser.py`, `hh_web.py`, `run_web.py`.
- **Официальное API** — запасной, только поиск гарантированно работает; отклик может
  не пройти (403). Файлы: `hh_client.py`, `run.py`.

## ⚠️ Риски браузерного варианта

Автоматизация UI против правил hh.ru. Риск — **бан твоего личного аккаунта** (на нём
резюме и история). Капчу инструмент НЕ обходит: при её появлении встаёт, проходишь руками.
Держи паузы и малый объём за прогон.

## Установка

```bash
cd ~/Desktop/hh-autoapply
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
playwright install chromium
cp .env.example .env      # заполнить фильтры (SEARCH_TEXT, AREA, SALARY_MIN, стоп-слова)
```

## Запуск (браузер)

```bash
python login.py       # откроется браузер — залогинься руками, вернись, нажми Enter
python run_web.py     # прогон; по умолчанию DRY_RUN=1 (кнопку отклика НЕ жмёт)
```

Логин делаешь ты сам в открывшемся окне — пароль скрипт не видит, сохраняется только
сессия в `state/session.json`.

## Калибровка (shadow → бой)

1. Гоняй `python run_web.py` при `DRY_RUN=1`. Финальная кнопка не нажимается.
2. Смотри `state/decisions.jsonl`:
   - `would_apply` — куда откликнулся бы,
   - `below_threshold` — счёл слабым,
   - `reject` — отсёк HARD-фильтр,
   - `no_button` — кнопки отклика нет (уже откликался / закрыта / сменился селектор).
3. Правь пороги в `.env` и логику в [decide.py](decide.py) (сейчас скоринг и письмо —
   заглушки; заменить на LLM).
4. Лог выглядит адекватно → `DRY_RUN=0`. Порог держи высоким, объём — низким.

Если что-то перестало находиться на странице — селекторы hh.ru собраны в одном месте:
`SEL` в [hh_web.py](hh_web.py). Проверять на живой сессии.

## Предохранители

- `DRY_RUN` — боевой отклик выключен по умолчанию.
- `DAILY_LIMIT` — потолок откликов за прогон.
- `SCORE_THRESHOLD` — ниже порога не откликаемся.
- `PAGES_PER_RUN`, `PAUSE_SECONDS` — объём и паузы против антибота.
- дедуп по `state/seen.json`.
- HARD-фильтры (зарплата, стоп-слова, чёрный список) — до скоринга.
