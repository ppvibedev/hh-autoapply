# hh-autoapply — описание и инструкция

Инструмент для автоматического поиска подходящих вакансий на hh.ru и отклика на них
с сопроводительным письмом, сгенерированным ИИ. Личный инструмент. Работает локально
на твоём компьютере, наружу ничего не публикует (слушает только 127.0.0.1).

---

## 1. Что делает

За один «прогон» бот сам, без участия человека:

1. **Ищет** вакансии на hh.ru по твоим фильтрам (запрос, регион, зарплата, опыт и т.д.).
2. **Отсекает** неподходящие (стоп-слова, чёрный список компаний, зарплата ниже порога).
3. **Оценивает** каждую оставшуюся (скор 0–100 по совпадению с запросом в названии).
4. **Генерирует письмо** под конкретную вакансию: ИИ берёт требования вакансии и твоё
   резюме и пишет сопроводительное, подтверждая опыт под требования.
5. **Откликается** на вакансии со скором ≥ порога, прикрепляя письмо и выбранное резюме.
6. Останавливается по достижении дневного лимита откликов.

Поиск и отклик идут **через сайт hh.ru под твоей залогиненной сессией** (браузер
Playwright), потому что официальное API не даёт сторонним приложениям отправлять отклики.

---

## 2. Как проходит прогон (по этапам)

```
для каждой страницы выдачи (PAGES_PER_RUN):
  поиск вакансий по фильтрам
  для каждой вакансии:
    уже видел (дедуп)? → пропуск
    HARD-фильтр (стоп-слово / чёрный список / зарплата) → отбой
    открыть карточку → скоринг (0–100)
      скор < порога → «мимо», не откликаемся
      скор ≥ порога:
        лимит исчерпан? → стоп
        сгенерировать письмо (ИИ по вакансии + резюме)
        отправить отклик (письмо + резюме)
```

Каждое решение пишется в ленту на дашборде и в лог `state/decisions.jsonl`.

## 3. Состав программы

| Файл | Назначение |
|---|---|
| `webapp.py` | локальный веб-сервер дашборда (Flask) |
| `web/index.html` | сам дашборд (интерфейс) |

| `llm.py` | обращение к ИИ (Claude / OpenAI / YandexGPT) |

| `config.py`, `envfile.py`, `.env` | настройки |
| `hh_client.py`, `run.py` | запасной путь через официальное API (только поиск надёжен) |
| `setup.sh`, `start.sh`, `cleanup.sh` | установка / запуск / очистка |

## 4. Установка

Нужен **Python 3.9+** (`python3 --version`). В папке проекта один раз:

```bash
bash setup.sh
```

Создаст окружение, поставит зависимости и браузер Chromium (2–3 минуты).

---

## 5. Запуск и первый вход

Самый простой способ — **двойной клик по `hh-autoapply.command`** в Finder: он поднимает
дашборд и сам открывает браузер. При первом запуске он же поставит окружение, если нужно.

Первый двойной клик может дать предупреждение macOS («из неустановленного источника») —
тогда: правый клик по файлу → **«Открыть»** → «Открыть» (это разово, дальше двойной клик).

Альтернатива из терминала:

```bash
bash start.sh
```

Дашборд — **http://127.0.0.1:8000**. Чтобы остановить приложение — закрой окно терминала,
которое открыл ярлык. Далее:

1. Блок **«Вход в hh.ru»** → «Открыть окно входа» → в открывшемся окне **залогинься руками**
   (логин, пароль, при необходимости капча) → вернись в дашборд → «Я вошёл — сохранить».
   Бейдж вверху сменится на «сессия есть». Пароль инструмент не хранит, только сессию.
2. Блок **«Резюме для отклика»** → «Обновить список резюме» → выбери резюме под роль.
3. Блок **«ИИ для писем»** → выбери провайдера, впиши API-ключ → «Сохранить».
4. Выстави фильтры → «Запустить прогон».

---

## 6. Интерфейс (дашборд)

- **Вверху** — бейдж режима («БОЙ» — отклики реальные) и статус сессии.
- **Красный баннер** сверху — виден, только пока идёт прогон, с кнопкой «Стоп».
- **Кнопки:** «Запустить прогон», «Стоп» (останавливает всё), «Сбросить историю»
  (чистит ленту и список просмотренных — нужно для чистого повторного прогона).
- **«Итоги (весь лог)»** — счётчики: отклики, мимо, отбой и т.д.
- **«Фильтры и режим»** — все настройки (см. ниже), кнопка «Сохранить».
- **«Лента решений»** — что бот сделал по каждой вакансии; у откликов раскрывается письмо.
- **«Лог прогона»** — технический вывод.

Уведомления (тосты) в правом верхнем углу подтверждают каждое действие.

---

## 7. Настройки и фильтры

Фильтры поиска повторяют поиск hh.ru:

| Поле | Что делает |
|---|---|
| **Что ищем** (SEARCH_TEXT) | поисковый запрос; ищется **только в названии** вакансии |
| **Регион / город** (AREA) | вся Россия / регион / конкретный город |
| **Зарплата от** (SALARY_MIN) | порог зарплаты, ₽ (передаётся в поиск hh) |
| **Формат работы** (WORK_FORMAT) | любой / можно удалённо (удалёнка+гибрид) / только полная удалёнка |
| **Опыт работы** (EXPERIENCE) | нет опыта / 1–3 / 3–6 / 6+ |
| **Тип занятости** (EMPLOYMENT) | полная / частичная / проектная / стажировка |
| **График работы** (SCHEDULE) | полный день / сменный / гибкий / удалёнка / вахта |
| **Период публикации** (SEARCH_PERIOD) | сутки / 3 дня / неделя / месяц / всё время |
| **Сортировка** (ORDER_BY) | по дате / соответствию / зарплате |

Свои фильтры (сверх hh, для автоотклика):

| Поле | Что делает |
|---|---|
| **Стоп-слова** (STOPWORDS) | если слово есть в названии — вакансия отсекается |
| **Чёрный список компаний** (BLACKLIST_EMPLOYERS) | эти компании пропускаются |
| **Порог отклика 0–100** (SCORE_THRESHOLD) | ниже порога не откликаемся |

Предохранители и объём:

| Поле | Что делает |
|---|---|
| **Лимит откликов за прогон** (DAILY_LIMIT) | максимум откликов за один запуск |
| **Страниц за прогон** (PAGES_PER_RUN) | сколько страниц выдачи разбирать (~50 вакансий/стр.) |
| **Пауза, сек** (PAUSE_SECONDS) | задержка между действиями (защита от антибота) |

## 8. Как принимается решение

- **HARD-фильтры** (в `decide.py`): чёрный список, стоп-слова в названии, зарплата ниже
  минимума → отбой ещё до скоринга.
- **Скоринг:** запрос разбивается на слова (длиннее 2 букв); считается, сколько из них
  встречается **в названии вакансии**; скор = доля × 100. Порог по умолчанию 90 → для
  запроса из 2 слов проходит только 100 (оба слова в названии).
  Это эвристика: она видит слова, но не понимает роль/грейд — например «Заместитель
  коммерческого директора» по названию тоже даст 100. Точную оценку роли даёт ИИ-скоринг
  (в базовой версии не включён).
- **Письмо:** ИИ (`llm.py` + `decide.cover_letter`) получает описание вакансии и текст
  выбранного резюме и пишет письмо: выделяет требования вакансии и под каждое показывает
  релевантный опыт из резюме. Правила: не выдумывать факты, плоский текст без разметки,
  без подписи. Если ИИ недоступен — уходит короткий шаблон.

---

## 9. Режим и предохранители

- **Режим только боевой** — отклики отправляются реально. Перед запуском — подтверждение.
- **Один прогон одновременно** — второй запуск блокируется, пока идёт первый (защита от
  дублей и превышения лимита). Активный прогон всегда виден красным баннером с кнопкой Стоп.
- **Дневной лимит** — жёсткий стоп по числу откликов.
- **Дедуп** — на одну вакансию откликаемся один раз (`state/seen.json`).
- **Пауза между действиями** — против антибота hh.

Быстрые вакансии, где hh отправляет отклик мгновенно без окна письма, помечаются
«отклик БЕЗ письма» — они уходят без сопроводительного (у таких письмо добавляется на
hh только вручную).

---

## 10. Результаты

- **Лента решений** на дашборде: статус по каждой вакансии, скор, у откликов — письмо.
- Статусы: `отклик + письмо`, `отклик БЕЗ письма`, `мимо` (ниже порога), `отбой`
  (HARD-фильтр), `нет кнопки` (уже откликались / вакансия закрыта).
- Файлы: `state/decisions.jsonl` — все решения; `state/seen.json` — просмотренные;
  `state/resume.txt` — кэш текста резюме.
- **Достоверный список отправленного — всегда в кабинете hh.ru** («Отклики и приглашения»).

---

## 11. Перенос на другой компьютер

1. Скопируй `hh-autoapply-transfer.zip`, распакуй.
2. `bash setup.sh` → `bash start.sh` → http://127.0.0.1:8000
3. Заново: вход в hh.ru, список резюме, API-ключ ИИ.

Не переносятся (создаются заново): `.venv`, `state/` (сессия — перелогинься),
`.env` (ключ — задаёшь через дашборд). Сессию лучше создавать заново: куки hh.ru
привязаны к устройству/сети.

---

## 12. Очистка данных

Стереть личные данные (сессия hh.ru, ключ ИИ, кэш резюме, лог) — особенно на чужом компе:

```bash
bash cleanup.sh
```

Полностью убрать инструмент — удали папку `hh-autoapply`.

---

## 13. Ограничения и типичные проблемы

- **Скоринг — по словам, не по смыслу.** По названию проходят и «замы»/«junior». Точную
  оценку роли даёт ИИ-скоринг (можно добавить).
- **Вёрстка hh меняется.** Если поиск/письмо перестали работать — селекторы собраны в
  одном месте: словарь `SEL` в `hh_web.py`. В ленте это видно как «нет кнопки».
- **Капча.** При высокой активности hh может показать капчу — прогон встанет, обходить
  капчу инструмент не будет. Помогают паузы и небольшой объём за прогон.
- **ИИ в РФ.** Claude/OpenAI могут быть недоступны без VPN; YandexGPT работает напрямую.
  Если письма падают в шаблон — проверь ключ и доступность провайдера.
- **Быстрые отклики** уходят без письма (см. §9).

---

## 14. Технические детали

- Дашборд: Flask, слушает `127.0.0.1:8000` (только локально).
- Браузер: Playwright + Chromium, работает под сохранённой сессией `state/session.json`.
- Источник правды по настройкам — файл `.env` (дашборд его и редактирует).
- ИИ: провайдер и ключ в `.env` (`LLM_PROVIDER`, `LLM_API_KEY`, для Yandex — `YANDEX_FOLDER_ID`).
- Запасной путь через официальное API (`run.py`) оставлен для поиска; отклик по API
  сторонним приложениям hh обычно не разрешает.
