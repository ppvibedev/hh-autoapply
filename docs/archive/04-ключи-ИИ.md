# Ключи для ИИ: куда вводить и что будет со старым

## Куда вводить ключ ИИ

На странице программы (**http://127.0.0.1:8000**), блок **«ИИ для писем»**:

- **Провайдер** — YandexGPT / Claude / OpenAI;
- **Модель** — можно оставить пустым (возьмётся по умолчанию);
- **Folder ID** — только для YandexGPT;
- **API-ключ** — сюда вставляешь ключ (поле-пароль);
- нажми **«Сохранить»**.

Если ключ уже задан, в поле будет подсказка «ключ сохранён — оставь пустым, чтобы не менять».

> Кто настраивает вручную — те же значения лежат в файле `.env`:
> `LLM_PROVIDER`, `LLM_API_KEY`, `YANDEX_FOLDER_ID`.

---

## Что будет со старым ключом, если вставить новый

### В программе
Новый ключ **перезаписывает** старый в `.env` — старое значение затирается,
программа дальше работает с новым. Логика при сохранении:

- вставил новый ключ → старый **заменяется** на новый;
- оставил поле **пустым** → старый ключ **остаётся** (не затирается). Так сделано
  специально, чтобы случайно не стереть.

### У провайдера (важно)
Замена ключа в программе **не отключает и не удаляет старый ключ** в Yandex Cloud /
OpenAI / Anthropic. Старый ключ там **продолжает действовать**, пока ты сам не отзовёшь
его в консоли провайдера.

| Действие | Что со старым ключом |
|---|---|
| Вставил новый в программе | Убран из твоего `.env`, программа им больше не пользуется |
| Но у провайдера | Старый ключ **всё ещё живой** — работает, пока не отзовёшь вручную |

---

## Вывод

Если старый ключ нужно реально «погасить» (например, он засветился) — мало заменить его
в программе. Нужно **отозвать / перевыпустить его в консоли провайдера** (Yandex Cloud,
OpenAI, Anthropic).
