## Уточнения к текущему коду

- Python: документация говорит 3.9+, но `llm.py` использует `str | None` без отложенного вычисления аннотаций; текущему коду требуется как минимум 3.10. Совместимость всех зависимостей проверяется отдельно.
- Локально работают интерфейс и движок. Приложение обращается к HH и отправляет текст вакансии и резюме выбранному LLM; фраза «полностью локально» не означает отсутствие передачи данных.
- Поддерживаются Anthropic, OpenAI, YandexGPT и Gemini. LLM используется и для скоринга названия, и для письма. Без доступного LLM работают эвристика и шаблон.
- `.env` находится в корне проекта, а не внутри `state/`.
- API-путь `run.py` содержит отправку через `/negotiations`, а не только поиск. Доступность отправки на стороне HH не проверялась.
- `setup.sh` также обновляет pip и создаёт `.env` из примера, если файла ещё нет. Размеры окружения и браузера в старой инструкции — приблизительные.
- Закрытие окна сервера не является гарантированной штатной остановкой дочернего прогона: код не содержит соответствующего обработчика завершения сервера.
- Новый LLM-ключ применяется при загрузке конфигурации новым процессом. Уже работающий прогон продолжает использовать загруженный ключ. Перезапись файла не отзывает ключ у провайдера.
- Список моделей и сведения о доступности сервисов в регионах в старых документах не проверялись на актуальность.

## Подтверждённые ограничения для планирования MVP

1. Пробный режим отключён: `config.DRY_RUN=False` независимо от `.env`. Указания README о безопасном shadow-запуске устарели.
2. Лимит откликов считается за прогон, а не за календарные сутки.
3. Успех отклика определяется по кликам и наличию элементов без подтверждения от HH. Выбор резюме и заполнение письма не гарантированы.
4. `seen.json` сохраняется в конце; принудительная остановка или ошибка могут потерять новые отметки. ID добавляется до проверки лимита и отправки, поэтому часть неотправленных вакансий может исключаться из повторных прогонов.
5. Журнал решений очищается при новом браузерном прогоне. Это не полная история откликов.
6. Защита от одновременных запусков не атомарна. PID не проверяется на принадлежность процессу проекта. Сброс истории доступен во время прогона.
7. Отдельного обнаружения капчи и истёкшей сессии нет. Наличие файла сессии не подтверждает действительный вход.
8. `/api/runlog` читает `state/run.log`, хотя фоновый процесс пишет `state/run_web.py.log`; счётчики не включают `applied_no_letter`.
9. HARD-фильтры применяются к карточке до загрузки подробностей; стоп-слова проверяются только в заголовке. Скоринг оценивает название, а не соответствие опыта кандидата описанию вакансии.
10. Зависимости не закреплены точными версиями. Настройки и файлы состояния не имеют полноценной валидации и атомарной записи.

Эти пункты — результаты чтения кода, а не разрешение на исправления или запуск реальных откликов.

## Как развивать документацию

Пока достаточно исходных пояснений и этой сверки: отдельные пять документов во многом повторили бы их. По мере доработки MVP выделять инструкции запуска, правила решений, описание состояния и список исправленных проблем в отдельные файлы, когда объём этого потребует.

Правила для помощника находятся в корневом `AGENTS.md`. Исключения файлов из Git находятся отдельно в `.gitignore`. 7 сентября 2026 года пользователь разрешил сохранить текущую промежуточную версию MVP в приватном репозитории GitHub без секретов и локального состояния. Этот снимок не означает, что перечисленные ограничения исправлены.
